How I built this

No engineers, no agency, no five different apps stitched together. I built this whole hub by talking to Claude in plain English. For the three of us it is simply where we keep our documents and our meeting record — you never have to touch the code. Here is what is running under it, and why building it this way is a preview of what we sell.

The short version

This hub is six web pages. I did not write the code for them by hand. I opened a tool called Claude Code, described what I wanted — “a page where we paste meeting notes and it files the decisions and action items” — and it wrote the code and put it live on the internet. When we want a change, I ask for it, and it changes.

That is the same kind of AI we are going to put to work inside businesses, the thing we are calling Scotty. So this hub is not just where we work. It is a small, working proof of what we do.

What Claude Code is

Claude Code is Claude — the AI you already know from chat — but with its hands on the actual files and tools instead of just talking back. It can read and write the code, run the commands, and publish the site. You brief it the way you would brief a developer, in plain words, and it does the work in minutes.

I am the one who built it and looks after the plumbing, so none of you have to. Day to day there is nothing to maintain and nothing to code: you open the site and use it, the way you would a shared drive. If we ever want it to do something new, I just ask for the change.

The pieces

A few free or nearly free services do the heavy lifting. Here is who does what.

The pagesVercel

The tabs you click are plain web pages, hosted on a service called Vercel. It takes our code and serves it at our web address. Nothing to install, nothing to log into — open the link and it is there.

The shared memoryRailway

The roadmap statuses, the message board, the meeting log, and the list of changes we have asked for look the same to all three of us because they are saved in a small database running on a service called Railway. One of us changes something, the others see it. That is what makes it a shared workspace and not three separate copies.

The file LibraryVercel storage

Decks, resumes, the business case — anything we drop on the Our Library page is kept in Vercel’s file storage. It gives us one shared drive built right into the hub, instead of emailing files around.

Scotty, the notes parserClaude API

When you paste meeting notes, the page hands them to Claude through its API — a direct line to the AI — and Claude hands back the decisions and the action items in a clean, consistent shape every time. That is a tiny version of exactly what Scotty does inside a business: take the messy input, do the thinking, return something useful.

How a change happens

1
One of us asks for a change
Any of us can send one from the Suggest a change box at the bottom of any page. It lands in a queue on Our RoadMap. I pick it up and brief Claude Code in plain words: “add a tab,” “change the wording,” “tighten that page.” No tickets, no spec.
2
Claude Code does the work
It edits the pages and the behind-the-scenes functions, and checks that they work.
3
It saves the new version
Every change is recorded on GitHub, which keeps a full history — so nothing is ever lost and we can always go back.
4
The site rebuilds itself
Vercel picks up the change and the new version is live at our address about a minute later. No “deploy day.”
5
The request clears itself
Once the new version is live, the suggestion that asked for it leaves the queue on its own, and the change is listed under What’s new on the Guide. Nobody keeps a to-do list tidy by hand.
6
If it is wrong, we say so
We look at it, and if something is off we just ask again. It is a conversation, not a project.

What that means for us

We could have hired an agency or bought five separate tools. Instead we built exactly what we need, we own all of it, and it costs almost nothing to run. For the two of you there is nothing to run and nothing to maintain — it is just there, like a drive that also files our meetings. The only things kept private are the keys that let the AI and the storage work, and those live safely in the hosting accounts, never in the pages themselves.

But the bigger reason is this: what I did to build this hub is a small version of what we are selling. We help good businesses bring this kind of AI in beside what already works, and stay until it carries the load. This hub is us doing it to ourselves first. Beam me up, Scotty.
