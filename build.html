How I built this

No engineers, no agency, no five different apps stitched together. I built this whole hub by talking to Claude in plain English. Here is what that means, what is actually running under it, and why it matters for what we are selling.

The short version

This hub is six web pages. I did not write the code for them by hand. I opened a tool called Claude Code, described what I wanted — “a page where we paste meeting notes and it files the decisions and action items” — and it wrote the code and put it live on the internet. When we want a change, one of us asks for it, and it changes.

That is the same kind of AI we are going to put to work inside businesses, the thing we are calling Scotty. So this hub is not just where we work. It is a small, working proof of what we do.

What Claude Code is

Claude Code is Claude — the AI you already know from chat — but with its hands on the actual files and tools instead of just talking back. It can read and write the code, run the commands, and publish the site. You brief it the way you would brief a developer, in plain words, and it does the work in minutes.

You do not need to know how any of it is built to change it. If Pat wants a new column on the Progress page, he can open the project and ask for it. That is the whole point: the people who use the thing can also change the thing.

The pieces

A few free or nearly free services do the heavy lifting. Here is who does what.

The pagesVercel

The tabs you click are plain web pages, hosted on a service called Vercel. It takes our code and serves it at our web address. Nothing to install, nothing to log into — open the link and it is there.

The shared memoryRailway

The progress statuses, the message board, and the meeting log look the same to all three of us because they are saved in a small database running on a service called Railway. One of us changes something, the others see it. That is what makes it a shared workspace and not three separate copies.

The file RepositoryVercel storage

Decks, resumes, the business case — anything we drop on the Repository page is kept in Vercel’s file storage. It gives us one shared drive built right into the hub, instead of emailing files around.

Scotty, the notes parserClaude API

When you paste meeting notes, the page hands them to Claude through its API — a direct line to the AI — and Claude hands back the decisions and the action items in a clean, consistent shape every time. That is a tiny version of exactly what Scotty does inside a business: take the messy input, do the thinking, return something useful.

How a change happens

1
One of us asks
In plain words: “add a tab,” “change the wording,” “log today’s meeting.” No tickets, no spec.
2
Claude Code does the work
It edits the pages and the behind-the-scenes functions, and checks that they work.
3
It saves the new version
Every change is recorded on GitHub, which keeps a full history — so nothing is ever lost and we can always go back.
4
The site rebuilds itself
Vercel picks up the change and the new version is live at our address about a minute later. No “deploy day.”
5
If it is wrong, we say so
We look at it, and if something is off we just ask again. It is a conversation, not a project.

What that means for us

We could have hired an agency or bought five separate tools. Instead we built exactly what we need, we own all of it, it costs almost nothing to run, and any of the three of us can change it by asking. The only things kept private are the keys that let the AI and the storage work, and those live safely in the hosting accounts, never in the pages themselves.

But the bigger reason is this: what I did to build this hub is a small version of what we are selling. We help good businesses bring this kind of AI in beside what already works, and stay until it carries the load. This hub is us doing it to ourselves first. Beam me up, Scotty.
